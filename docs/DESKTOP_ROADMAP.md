## 关键决定

### X 登录：用户自己的开发者应用 + PKCE

- **公开 EXE 不内置 Client ID，由用户填自己的。** 这是本轮调研最重要的结论：X 按开发者账号的预付额度计费，一个内置的 Client ID 意味着**所有用户的同步都从开发者本人的额度里扣**，而且官方的 US$0.001 / 条“自有数据”价只在“授权用户就是应用所有者”时才适用，其他用户按标准价计。用户用自己的应用则费用自负、价格最低，也不存在分享密钥的问题。代价是首次配置要多几步，设置页给出逐步说明。以后若决定由开发者代付，只需内置 Client ID，代码不用改。
- **类型 Native App，公开客户端，只用 PKCE**（S256），EXE 里没有 Client Secret，磁盘上也不保存。原 MySQL 方式的机密客户端刷新逻辑不变。官方表格（2026-11-02 核对）：Native App、Single Page App 是公开客户端，Web App、Automated App / Bot 是机密客户端并发放 Client Secret。官方没有写应用类型创建后能否修改，所以设置页建议新建 Native App，不让用户改动已有应用。
- **回调是独立的短时监听** `http://127.0.0.1:47392/x/callback`。X 要求回调地址完全匹配（官方：含末尾斜杠，本地开发用 `127.0.0.1`，不用 `localhost`），所以端口固定；从 x.com 跳回时 `SameSite=Strict` Cookie 不会发送，所以不走主服务，访问保护不用开洞。监听只接受这一次的 `state`，最长 5 分钟。授权码的官方有效期是 30 秒，回调到达后立即交换。
- **连接本身不产生计费调用**：只换 token，不读任何接口；只有用户点“同步”才读取，首次点击先说明费用。所以账号是否换过，要到第一次同步读 `/users/me` 时才知道，规则见 [X 同步文档](X_LIKES_SYNC_CONSISTENCY.md#进度属于哪个账号v8)。
- 权限范围：`tweet.read users.read like.read offline.access`。
- **一次登录的状态**：同一时间只有一个当前尝试。等待回调时可被取消、超时或被重新开始取代；回调到达后换 token 不持锁，尝试仍是当前的，此时取消、断开、重新开始都立即生效。只有仍持有当前尝试的回调才能保存 token 或报告结果，所以迟到的结果不会覆盖新状态，已签发的 token 会撤销（尽力而为）。5 分钟时限只管等待回调，已开始的交换由请求自身的 20 秒超时限定。取消重新授权时，原来连接的账号不受影响。

### X 费用与风险（官方页面，2026-11-02 核对）

| 项目 | 内容 |

| 计费 | 预付额度、无订阅，价目页没有免费档（只有首次购买的赠送活动）；按返回资源计费，同一资源 UTC 当日去重（官方称“软保证”）；失败的请求不计费；官方写明价格可能调整 |

| 每次同步上限 | 现有预算 100 条，约 US$0.10；另有一次 `/users/me`：它不在 Owned Reads 列表里，官方也没有写它的单价（通用 User: Read 是 US$0.010） |

### Gemini（官方页面，2026-11-02 核对）

- 由用户填自己的 API Key，存在 `<home>\config\gemini-key.txt`，EXE 不含密钥。`gemini-3.1-flash-lite` 有免费额度；付费档输入 US$0.25、输出 US$1.50 / 百万 token。Key 所属项目启用结算后属于付费使用，所以应用不能承诺免费。
- 免费额度下，提交的图片可能用于改进产品，也可能被人工审核；付费使用官方写明不用于改进产品。设置页已写明。
- Key 的限制有变化：2026-05-28 起 AI Studio 新建的是限定 Gemini API 的 auth key，API 会拒绝未加限制的标准 Key。所以旧 Key 能否继续用，只有实际调用才知道。官方的 `models.list` 只校验 Key 存在，不代表推理可用，这也是不做“测试连接”的另一个理由。
- 中国大陆、香港、澳门不在官方可用地区列表内。条款还写明面向专业或商业用途、不面向消费者，且使用者须年满 18 岁。公开发布时要把这些写进说明，不能把 AI 分析当作人人可用的功能。官方没有写明不支持地区的错误形式，所以应用把 400 / 401 / 402 / 403 统一说成“请到设置检查”，不判断具体原因。

### 配置的三种状态

本地图库开箱即用，X 与 AI 都是可选项，不做首次配置。设置页把三件事分开显示，互不代替：

| 状态 | X | AI | 依据 |
| --- | --- | --- | --- |
| 配置已保存 | Client ID 已保存在本机 | API Key 已保存在本机 | 本机文件 |
| 授权已连接 | 本机有桌面版能刷新的 token | 无此步骤 | 只看文件，不联网，不代表 X 仍然接受 |
| 真实功能已验证 | 当前登录完成过一次同步，显示 X 返回的账号和时间 | 当前 Key 完成过一次分析 | 用户主动触发的真实调用成功 |

每条验证记录都写明它证明的是哪次登录、哪个 Key，只有和当前使用的一致才显示。登录 ID 和 token 一起原子写入，Key 用不可逆的指纹比对，所以换掉凭据的同时旧记录就不再算数，不依赖之后能否写入 `settings.properties`，重启后也一样。开始于旧登录的同步，结束后既不能为新登录作证，也不能覆盖新登录已有的记录。没有“测试连接”：那是一次隐式的真实调用，X 上还可能计费。

### 应用窗口：SWT + WebView2（2026-10-30 选定，2026-10-31 迁移完成）

之前是 `msedge --app=<地址>`，加 Swing 控制窗和 SSE 判断关窗。它能用，但窗口不归应用所有：Edge 启动的进程会立刻退出，关窗只能靠页面的 SSE 在线通道（最后一个页面断开 8 秒后退出），右键菜单、F12 等都是浏览器的。

现在 JVM 主线程跑 SWT 事件循环，直接持有窗口和关闭事件；Swing 控制窗、`DesktopPresence` 和 `/desktop/presence` 已删除。Edge `--app` 只在缺少 WebView2 时作为回退，由一个 SWT 小窗提供“退出”。

选型时的隔离原型（同一份代码，只换窗口）：SWT 打进 Boot jar，jpackage 打包，用干净的用户数据目录，不传代理参数。

| 指标 | Edge `--app` | SWT + WebView2 |
| --- | --- | --- |
| 首个窗口 | 2.7 s（控制窗） | 1.6 s |
| 页面就绪 | 7.9 s | 约 7.5 s |
| 浏览器进程 | 14 个 | 6 个 |
| 图库页内存（JVM + 浏览器，工作集） | 1223 MB | 739 MB |
| X 收藏滚动 | 180 fps，P50 5.6 ms | 180 fps，P50 5.6 ms |
| 关窗到退出 | 12.5 s | 1.1–2.2 s |
| 包体 | 172 MB | 175 MB |

- 代理：不传参数时，WebView2 的外部连接只有系统代理和本机服务，127.0.0.1 直连。系统代理开启时 X 图片和 MP4 都正常。
- 媒体：H.264 MP4、`backdrop-filter` 正常。
- 关闭：H2 锁释放，无残留 WebView2 进程。

托盘（2026-10-31）：SWT 的 `TrayItem`，图标随窗口一起出现。默认每次询问，第一次关闭不会让应用不声不响地留在后台。WebView2 的可见性 SWT 只会设为真，隐藏窗口时要经反射调用 `put_IsVisible(false)`，否则后台继续满帧渲染；SWT 升级后若这条路断了，只是后台多耗资源，功能不受影响。

代价：SWT 3.133 起要求 Java 21，所以项目升到了 Java 21；SWT 不提供 WebView2 的自绘标题栏接口，只能用原生标题栏，再用 DWM 让它跟随主题（走 SWT 内部类 `OS`）。如果日后真的需要自绘标题栏，备选是 C# 薄壳 + WebView2 + Java 子进程。

没有选：Tauri（窗口引擎同样是 WebView2，却多一套 Rust 工具链）；Electron（仅官方包就 150.9 MB，还要自带升级节奏）；JCEF（官方 CEF 二进制默认不含 H.264）；JavaFX WebView（换引擎，整站要重新回归）；原生重写（推翻已验收的前端）。

### 启动耗时（同一 jar，到页面就绪，2026-10-30）

| 配置 | 耗时 |
| --- | --- |
| JDK 17 嵌套 jar（现状） | 7.6–8.3 s |
| JDK 17 解压布局 | 5.8–5.9 s（第一次 6.6 s） |
| JDK 21 解压布局 | 4.7–5.2 s |
| JDK 21 解压布局 + `-XX:+AutoCreateSharedArchive` | 4.1–4.2 s，归档 40 MB |

最终方案（2026-10-31）：解压布局 + 打包时生成的动态 CDS 归档，实测到页面就绪 3.0–3.4 秒，整体移动目录和从 zip 解压后都有效。

没有用 `-XX:+AutoCreateSharedArchive`：记录归档时每定义一个类都很慢（进程 20 秒只用 2 秒 CPU），让用户第一次启动来生成，那次要 56–68 秒。所以 `build-desktop.ps1` 打包时跑一次 `--train-class-data` 生成 `app\app.jsa`，运行时只读。归档校验 jar 的时间戳，脚本因此先把 jar 的时间设为偶数秒（zip 只保存这个精度）。归档不匹配时 JVM 自动忽略，退回约 6 秒的普通启动。

### X 图片：CDN 不接受本机 Referer

`pbs.twimg.com` 对 `Referer: http://127.0.0.1…` 或 `localhost` 返回 **HTTP 351 Forbidden**（2026-10-30 用 curl 复现）。浏览器把这个 `text/html` 响应拦成 `ERR_BLOCKED_BY_ORB`，干净配置的 Edge 里旧页面 0/39 张加载成功。

两个 Inbox 页面因此都声明 `<meta name="referrer" content="no-referrer">`。这不影响 `LocalAccessFilter` 的 Origin 校验：同源 `fetch` 是 cors 模式，Origin 不变（已实测）。列表用官方的 `name=small`，预览用 `name=large`；归档走 Java，不带 Referer，仍取 4096 大图。

修复后仍然读不到的媒体，用户核对过，对应 X 上已删除、隐藏的帖子或被冻结的账号，属于上游不可访问。处理方式就是占位、手动重试和“打开原帖”，不自动删除收藏记录，也不为此调整代理或图片架构。

### 数据迁移：只读旧库、写新目录

- 命令见 [DESKTOP_POC.md](DESKTOP_POC.md#mysql-数据迁移2026-10-30)。不加 `--execute` 时完整试跑到内存数据库，一个文件都不写。
- 目标目录必须不存在或为空，否则直接拒绝。写入先进临时目录，全部行数与 SHA-256 核对通过后才改名就位；失败不留任何东西。
- MySQL 用只读事务、单一快照，媒体只读。ID 原样保留，所以 Inbox 与作品的关联、同步检查点都有效。
- 不迁移 X token：旧 token 属于机密客户端，桌面版要重新授权一次。
- 源库必须和应用处在同一 migration。V8 之后，停在 V7 的 MySQL 会被拒绝，需要先用新版启动一次 MySQL 模式完成迁移。
- H2 反向迁回 MySQL 不做，没有实际需求。

#### R3.1 安装器计划（2026-11-02，开发中）

目标是把现有自带 Java 21 的 `jpackage --type app-image` 包成按用户安装的 EXE。沿用 Inno Setup，不另换桌面壳或打包体系。以下是实施基线，未新增真实数据操作授权。实现与当前验证状态见 [DESKTOP_POC](DESKTOP_POC.md#安装器r312026-11-02)。

**范围与关键设计**

| 项 | 实施基线 |
| --- | --- |
| 平台与权限 | 先验收 Windows 11 x64；不据此宣称 Windows 10 或 ARM64 已支持。`PrivilegesRequired=lowest`，不提供提权安装选项；程序默认装到 `%LOCALAPPDATA%\Programs\IllustrationArchive`，卸载注册在当前用户下 |
| 安装身份与版本 | 固定 `AppId`，后续版本不更换；沿用上次安装目录。安装器构建必须显式传入同一数字版本，贯通 jpackage 的 EXE 元数据和 Inno `AppVersion`，拒绝不一致。允许同版重装和新版覆盖，拒绝低版本覆盖；版本号由用户决定，不用 Maven 的 `0.0.1-SNAPSHOT` 推断发布号 |
| 快捷方式与图标 | 当前用户开始菜单入口，加可选桌面快捷方式，复用 `packaging/icon/app.ico`；目标为安装目录中的 EXE，任务栏标识与现有 `IllustrationArchive` 一致。完成页“立即启动”默认不勾选，静默安装不自动启动 |
| 图库与配置 | 安装器不创建、迁移或清理数据 home，不改全局环境变量。保持 `DesktopServer.defaultHome()` 的规则：默认 `%LOCALAPPDATA%\IllustrationArchive`，旧 PoC 目录回退和显式 home 覆盖仍有效。安装目标不能与已知数据目录及其父子目录重叠；安装阶段不运行 Flyway |
| 正在运行 | 覆盖安装和卸载前，在安装器中检查目标 EXE 的实际进程路径，并在首次改文件前复查；仍在运行就提示从托盘“退出”后重试，检测失败不能当成未运行。前台和托盘态都要覆盖，不误拦其他路径的隔离包。关闭 Inno 自动关应用 / 重启应用（`CloseApplications=no`、`RestartApplications=no`），不强杀、不把替换文件延到重启；最后的文件占用错误也不能跳过后报告成功 |
| 文件替换 | 使用 Inno 的逐文件覆盖与卸载记录，不先清空程序目录；处理旧 JAR 时只定向清理安装器管理的程序文件，禁止 `{app}\*` 式宽泛删除。新旧文件即使有相同的固定时间戳也必须正确替换；显式保留 UTC 时间戳（`TimeStampsInUTC=yes`），不在安装后改写 JAR，保护现有 CDS 归档 |
| 卸载与重装 | 只移除安装器登记的程序、快捷方式和自身注册信息；保留 home 下数据库、媒体、配置、凭据、日志及旧 PoC 目录，不提供清空图库选项，不卸载共享 WebView2。重装应能再次打开保留的库；程序重装不等于数据库降级恢复 |

`DesktopLauncher` 目前使用 home 下的 `instance.lock` 文件锁，没有创建 Windows 命名互斥量，不能只填 Inno `AppMutex` 就声称能拦截运行中升级。首选把检查放在安装器，避免为此增加 Java 原生桥接依赖；先用真实前台 / 托盘进程验证检测，再完成安装脚本。

**WebView2 安装流程**

1. 按微软文档读取 HKLM 的 32 位 EdgeUpdate 视图与 HKCU 对应 Runtime 项的 `pv`；至少一处是大于 `0.0.0.0` 的有效版本才算已安装，不能用“有 Edge 浏览器”替代。可用时复用，不运行 Bootstrapper。
2. 构建时接收来自微软官方的本地 Evergreen Bootstrapper，校验 Authenticode 签名和发布者并记录其 SHA-256。将这个小引导程序内置到安装器；完整 Runtime 仍需安装时联网下载，不承诺缺少 Runtime 时也能离线安装。工具和下载缓存放在仓库外。
3. 缺失时在修改应用文件前，明确说明需要下载并安装运行环境，以非提权方式执行 `MicrosoftEdgeWebview2Setup.exe /silent /install`，等待结果后重新检测 `pv`。微软说明它可在非提权进程下安装，已有系统级 Edge Updater 可能统一管理它。
4. 安装失败或复查仍不可用时，给出失败信息及重试 / 取消入口，不继续报告完整安装成功；已有应用文件应未被修改。不调整代理、DNS 或运行时更新策略来重试。现有 Java 回退逻辑保留，但不能替代这条安装流程的验证。

**实施顺序与文件**

1. **构建输入**：在仓库外的源码副本中使用 `scripts/build-desktop.ps1`，增加统一的版本参数，保留现有镜像、ZIP 和打包前扫描。不可在原仓库运行会删除 `target/classes` 的构建。开发前准备 Inno 编译器路径和签名有效的 Bootstrapper。
2. **安装脚本**：新增 `packaging/installer/IllustrationArchive.iss` 与 `scripts/build-installer.ps1`。包装脚本只接收显式应用镜像、版本、编译器和 Bootstrapper 路径，核对镜像版本，再复用 `check-desktop-package.ps1` 扫描后编译，不从工作目录兜底搜集文件。实现版本比较、运行阻断、前置 Runtime 安装和保留数据的卸载。
3. **隔离验证**：在 `D:\Temp\ia-r31-*` 放源码副本、合成图库、日志与结果。准备两个实际内容不同的版本覆盖，检查新字节和旧程序文件处理，不能仅改版本号。配置内使用假凭据标记，不复制已登录验收 home 或原图库。
4. **交接**：开发方完成 A 级检查并保存改动，用户提交后再把明确提交和候选包交给 Codex 做 C 级验收；缺陷由 Claude 修复，复验受影响路径。实现细节记入 `DESKTOP_POC.md`，当前状态和交接只保留摘要。

R3.1 只补安装 / 升级识别必需的版本参数；候选包命名、对外交付校验文件与随包说明仍属 R3.2。备份恢复 UI、旧库导入 UI、签名和自动更新均不并入此包。

**验收出口**

| 级别 | 本包应提供的证据 |
| --- | --- |
| A：开发方 | PowerShell 解析、Inno 编译、包内敏感信息扫描；缺参 / 版本不符 / 无效 Bootstrapper 被拒绝；运行检查、按数字分段的版本比较（含 `1.10` 与 `1.9`）、Runtime 检测和失败分支的针对性验证。仅脚本和打包改动不重跑已通过的 Java / JS 全量；如实际改到 Java，再按受影响路径补测试 |
| C：Codex | 隔离环境中首次安装、同版重装、新版覆盖、降级拒绝、运行中升级 / 卸载阻断、卸载后重装；核对快捷方式与当前用户卸载项。启动后以行数 / 业务字段、媒体哈希和假配置内容验证保留；卸载前先退出，停机状态下逐文件哈希核对整个 home 未变。检查安装后 JAR 时间戳及 CDS 是否仍被使用，不能仅凭“能启动”通过 |
| B：用户 | 实现后在状态表新增一次安装向导、快捷方式和安装后双击体验项；从专属桌面验收快捷方式启动隔离库，不重复列现有托盘 / 观感事项，不阻塞后续包 |
| R3.5 保留项 | 无 Java、缺少 WebView2 的真实 Bootstrapper 安装、离线失败和 SmartScreen 在可还原的干净 Windows 环境实测。模拟检测或假安装器不能关闭这些项目；不卸载本机共享 Runtime 或修改真实注册表来制造缺失，环境未准备时明确 `UNVERIFIED` |

优先用隔离 Windows 用户或可还原测试环境验证默认目录。若先在本机验证，禁止安装完成后直接启动默认 home：由专属桌面快捷方式调用受控脚本，仅对子进程设置 `ILLUSTRATION_ARCHIVE_DESKTOP_HOME`，指向合成图库。现有“插画档案 手动验收”快捷方式与已授权 X 副本不改动。原图库 V8 升级、真实 MySQL、X / Gemini 调用仍按状态表授权，不由安装器计划扩大。
